# Testing Standards

## Principles
- Tests exist to catch regressions and document behavior, not to raise a coverage number.
- Deterministic: fixed seeds, no wall-clock sleeps (use fake clocks/events), no reliance on external network.
- Fast by default. Slow/GPU/e2e tests carry markers and run in a separate CI job.
- Tests that need credentials or a GPU must skip cleanly when absent, never fail.

## Layers
| Layer | Purpose | Notes |
|---|---|---|
| Unit | Pure logic, state machines, validators | fast, no IO |
| Integration | Components with real DB/queue/storage (containers or embedded) | |
| API / contract | Every public endpoint; schema conformance; error shapes | derive from the API spec |
| Black-box | Drive the system only through public interfaces (CLI/API) | |
| Failure-path | Injected faults; assert recovery and state | see catalog |
| End-to-end | Full workflow on tiny real/synthetic data | few, high value |

## Failure-mode catalog (each needs at least one test once the feature exists)
- Corrupt / truncated / missing input data
- Worker crash mid-job; worker heartbeat loss
- GPU OOM (simulated where no GPU); GPU absent
- Timeouts (job-level and per-call)
- Network failure / partial response
- Duplicate submission (idempotency)
- Partial pipeline execution and resume
- Invalid configuration
- Missing dependency / missing artifact
- Cancellation at each lifecycle state
- Disk full / storage unavailable

Maintain the catalog with status per mode in [failure-modes.md](failure-modes.md) (drafted in phase 03; add test references as features land).

## Coverage
- 70% total branch coverage floor, enforced by pytest-cov in CI; ratchet upward only; lowering requires an ADR (ADR 0011).
- Branch coverage preferred where the tool supports it. Coverage is a floor, not a goal.

## Fixtures
- Small, synthetic, generated by code where possible. Commmitted fixtures live in `tests/fixtures/` and stay under 1 MB total per dataset.

## Shared integration state
Integration tests run against one persistent PostgreSQL database (`<dbname>_test`, created on demand by
`tests/conftest.py`) that is never truncated between runs. Two consequences, both of which have shipped a
red suite:

- **A test cannot assume it is first.** `claim_job` is FIFO over the whole catalog, so a job submitted by
  one test is only reached after every older queued job, from any test or any earlier run, has been
  processed. A drain loop bounded by a fixed iteration count is therefore a flake with a long fuse: it
  passes in isolation, passes on a rerun of the same directory, and fails once in a full random-order run
  when the backlog crosses the bound. Loop until the job you submitted has left the queue, or until
  nothing is claimable -- never until a counter runs out. It still terminates, because a job that keeps
  failing spends its own attempt budget.
- **Jobs left queued accumulate forever.** A test that forces a job into an unclaimable state (for
  example `attempts = max_attempts` while still `queued`) leaves a permanent row that inflates queue-depth
  assertions and counts for later runs. Prefer asserting on state transitions over manufacturing rows that
  nothing will ever clean up.

When investigating an integration failure, check the shared database before suspecting the code under test:
leftover rows from earlier runs are invisible from the test that trips over them.
