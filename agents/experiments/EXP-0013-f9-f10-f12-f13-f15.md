# EXP-0013: F9 / F10 / F12 / F13 / F15 — measured outcomes and open drill eligibility

- **Date (UTC):** 2026-10-03
- **Author/agent:** Buffy (Freebuff)
- **Status:** done (measured coverage closed; destructive live drills deferred by machine/DB constraints)
- **Related ADR / requirement:** NFR-006 (data durability), NFR-007 (GPU/resource), NFR-008 (observability), ADR 0008 (telemetry can't break the pipeline), ADR 0015 (job lifecycle)

## Hypothesis / purpose

Stage 5 fault injection targets F9 (disk full / artifact write failure), F10
(Postgres down mid-run), F12 (GPU OOM / GPU absent), F13 (telemetry/log sink failure),
and F15 (orphan blob / stale staging-dir reclamation). Some rows had `planned`
coverage that was carried by store-level and API-level tests in stage 3; the destructive
live-drill arms (a real `ENOSPC`, a live Postgres restart mid-run, a CUDA OOM) were
deferred because this sandbox has no quota-ed filesystem and no GPU. This record records
what was measured in each arm and what is still eligible to run against a real cluster.

## Change under test

Blameless audit of the existing, measured coverage for F9/F10/F12/F13/F15:

| Row | Measured coverage | Honest status |
|---|---|---|
| F9 | Store `put_bytes`/`put_file` contract (content-addressed, checksummed, empty-refusal, corrupt-detection) + a real SQL integration where `OSError` with `errno == ENOSPC` settles the job `failed` on attempt 1 with reason code `IO_DISK_FULL`; `episodes_produced_by` returns nothing for the job, and no artifact/episode/lineage row dangles | **Covered at store + SQL layer.** The pure "fill a real volume to ENOSPC then ingest" drill is eligible on a host with a quota-ed mount, not here. Store-level proof is the durable evidence. |
| F10 | API answers a Postgres outage with 503 + `Retry-After` (not 500); the worker loop survives the same outage without dying; every job state transition is a single transaction so nothing is lost while the queue is unreachable | **Covered for the observable behaviour.** The destructive "stop the live cluster, let the worker time out, restart, watch it recover" drill is stage-5-final work; the observable guarantees are pinned by contract/unit tests (`tests/contract/test_ingest_api.py`, `tests/unit/test_cli.py`). |
| F12 | No GPU work runs in the engine (`workloads/sdk.py` is an unimported 28-line Protocol), and telemetry degrades without GPU (every field nullable, `system_*` GPU gauge absent). The `gpu_required` rejection has no consumer yet, so there is no driver to OOM | **Honest outcome:** an engine that runs no GPU workloads has no GPU OOM to inject. The NFR-007 constraint ("CPU-only fallback works transparently") is met by construction: every resource field is nullable and the GPU probe is best-effort. A GPU-OOM test is deferred because there is no GPU user to report and no CUDA path to OOM. |
| F13 | A metrics sink that raises is logged once and swallowed (`test_runtime_metrics_swallows_sink_failures`); a recorder with no sink is a no-op; the pipeline emits correctly with a sink present (`test_worker_emits_queue_job_and_stage_metrics_on_success`) | **Covered end to end.** A telemetry failure cannot break the pipeline — this is the core of ADR 0008, and it is deterministic. |
| F15 | The artifact store publishes atomically (`mkstemp` + `os.link`, unlink in `finally`) so no half-written blob can sit at a content address; a failing export removes its `.pending-*` tree in a `finally`. A killed process can still leave a `.pending-*` directory because cleanup is in-process; `de gc` prints "no garbage collection is implemented" and is a manual operation | **Covered for the parts that exist.** The collector itself is intentionally unimplemented so `de gc` is a documented manual operation, not a false success. F15 is therefore a runbook/troubleshooting item, not a code change. |

## Configuration

- Workload: the same synthetic ingest, MCAP reader, and catalog queries used across the
  stage 3–4 campaign (`scripts/scale_campaign.py` conventions, isolated throwaway Postgres).
- Environment: `just ci` local gate; no quota-ed filesystem, no GPU device, no live
  multi-node cluster. Failures are reproduced at the unit/SQL/contract layer.
- Result file: `tests/unit/test_worker.py`, `tests/integration/test_job_lifecycle.py`,
  `tests/contract/test_ingest_api.py`, `tests/unit/test_metrics.py`,
  `tests/unit/test_artifacts.py`.

## Results

| Row | What was measured | Measured outcome | Verdict |
|---|---|---|---|
| F9 | `OSError(errno.ENOSPC)` → `IO_DISK_FULL` settlement; no dangling artifact/episode/lineage | Job `failed` on attempt 1, zero default attempts left; store refuses empty artifact; corrupt blob detected | **Met at layer**. Live-quota drill deferred |
| F10 | 503 + `Retry-After` on API outage; worker loop survives; single-transaction state transitions | No 500s on outage; queue survives; nothing lost | **Met at layer**. Live-restart drill deferred |
| F12 | No GPU workload; nullable telemetry; absent GPU gauge | CPU-only path works transparently; `gpu_required` rejected by nothing (stub) | **Honest outcome**: no driver to OOM. Deferred until a GPU user exists (NFR-007 follow-up). |
| F13 | Sink raises → one log line, swallowed; no-sink recorder → no-op; pipeline correct with sink | Telemetry cannot break the pipeline | **Met end to end** |
| F15 | Atomic publish + `finally` cleanup; `.pending-*` reclamation is manual | No half-written blob reachable; GC is documented manual | **Met for parts that exist**. Collector deferred (manual op) |

## Trade-offs

- **Live-drill defers are deliberate, not gaps.** F9/F10/F12 require a quota-ed mount,
  a live single-node Postgres, and a GPU device respectively; the sandbox cannot supply
  any of them. The store/API/contract layers that pin the behaviour are deterministic
  and committed near the code, so the measurements stand as the stage-5 evidence.
- **F12's "test" is a sketch, not a run.** A CUDA-OOM test instruments a nonexistent
  consumer and would be a false-positive test of a stub. The honest record is that the
  engine has no GPU runtimes and that the CPU fallback is the actual NFR-007 behaviour.
- **F15's collector is a documented manual operation.** Reclaiming a killed process's
  `.pending-*` tree is deliberately left to `de gc` / operators, so the row records what
  exists rather than shipping a stub GC and calling it closed.

## Conclusion

Decision: **adopt the measured-coverage evidence** for F9/F10/F13/F15 and **defer the
destructive live-drill arms** (F9 quota, F10 restart, F12 GPU) as machine-constrained.
F13 is closed end to end with no open arms. F9/F10 live drills become eligible when a
host with a quota-ed mount and/or a real isolated Postgres cluster is available.

## Follow-ups

- F9/F10 live-drill runbook (state recovery, artifact re-hash, catalog verify) — a
  docs-only write, eligible once a live cluster is available.
- F12: add a GPU workload consumer so the `gpu_required` admission path has something to
  reject and a CUDA OOM has something to report. Baseline for that follow-up is the
  telemetry-degrades-without-GPU tests.
- F15: turn the `.pending-*` documentation into a runbook section and re-verify `de gc`
  output against a killed-export scenario on a test host.
