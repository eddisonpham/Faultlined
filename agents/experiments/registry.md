# Experiment Registry

EXP-0001 through EXP-0008 are the scaffolding/MVP/production-baseline measurements. EXP-0009 records the current-tree stage attribution (where ingest time goes, per stage). EXP-0010a–e are the Performance/Scaling (stage 4) campaign: data-size ingest linearity, worker-count scaling, 10k-episode catalog scale (NFR-003 read latency + NFR-002 validate throughput), queue-latency/cancel decomposition (NFR-005), and API latency at 10 rps (NFR-010, which exposed and fixed a metrics-endpoint N+1). EXP-0011 opens stage 5's fault injection: real hard kills of real workers mid-ingest (NFR-006/F5), which also exposed and fixed a standalone-worker exit defect. EXP-0012 closes F6's mid-handler deadline gap. EXP-0013 records measured coverage for F9/F10/F12/F13/F15 and the deferred live-drill eligibility. A harness unit test is still not an experiment record. EXP-0014–0017 are the 2026-10-04 whole-program assessment: what the ingest path does with data that is not LeRobot or MCAP-JSON, per-feature latency for the entire shipped surface at three catalog scales, concurrent operator workflows sharing one catalog, and the operator's click and attention budget measured off served HTML. EXP-0018 validates the first fix out of that assessment: the monitor is scheduled by the worker loop under a catalog lease, so an incident exists without a manual webhook, at a cadence cost inside EXP-0016's band. EXP-0019 opens the curation programme: it calibrates the deterministic behavioural fingerprint against planted re-recordings and measures its cost, invalidating the first shipped threshold (0.10 → 0.04), finding two defects in its own corpus generator, and cutting the scoring cost 3.4× with a sound shortcut whose output is bit-identical. See [benchmark backlog](../benchmarking/backlog.md) and [methodology](../benchmarking/methodology.md).

## Future / deferred ideas

| Idea | Why deferred | Revisit when |
|---|---|---|
| Real LeRobot benchmark at scale | The LeRobot reader and fixture exist and `lerobot-ingest-v3` is measured (EXP-0002), but only a 203-frame tabular slice; no image/video shard benchmark | A full-episode real LeRobot ingest workload is scheduled |
| Queueing, end-to-end, failure recovery, scaling, startup, and efficiency metrics | Queue/failure metrics are emitted but nothing aggregates them into a benchmark result; lifecycle and production components are incomplete | B-004 aggregation is implemented and the job lifecycle exists |
| OpenTelemetry tracing | Correlation IDs and one local API/worker topology are sufficient for this slice | At least three independently communicating services or a trace-driven incident; supersede ADR 0008 |
| Prometheus exposition / dashboard | No scraper and no operational UI exist | A real scrape/alert or dashboard use case exists |
| Learned multivariate anomaly detection for monitoring | Superseded as the MVP by deterministic rules and control limits; would need ≥ 30 days of real telemetry and ≥ 200 labelled incidents from the unlabelled-events channel, and must beat rules on Tier-3 faults without exceeding the FP budget | Those labels exist, and a held-out comparison exists (ADR 0020, plan §11 Phase 3) |
| F9 live quota drill | Requires a quota-ed filesystem mount; sandbox has none | A host with a quota-ed mount and/or a real isolated Postgres cluster |
| F10 live DB restart drill | Requires stopping a live single-node Postgres mid-run | A real isolated Postgres cluster available |
| F12 GPU OOM drill | The engine runs no GPU workloads, so there is no driver to OOM | A GPU workload consumer exists (NFR-007 follow-up) |
| F15 orphan-blob collector | Deliberately manual; no false-success GC | A killed-export scenario on a test host to re-verify `de gc` output |
