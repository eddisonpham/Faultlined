## Current harness boundaries

`benchmarks/harness.py` runs three warmups and ten measured trials for a synthetic in-memory catalog plus real local filesystem artifact store, and one warmup and five trials for the real-data workloads (B-002, B-003), which are end to end over a file on disk. It preserves raw trial latencies and host resource snapshots. `DEFAULT_BASELINE` is the fixed path `benchmarks/baselines/synthetic-ingest-windows.json`; a baseline is committed there and `just bench` compares against it. B-002's baseline is written to `benchmarks/baselines/mcap-ingest-windows.json` via `just bench --workload mcap-ingest --write-baseline --baseline <path>`, because the harness's regression comparison and `DEFAULT_BASELINE` are specific to the synthetic workload. The real-data workloads are measured against their own committed baseline by eye, not by the automatic >20% rule. Raw per-run results stay ignored under `benchmarks/results/`, so a committed baseline's `source_run_id` resolves only on the measuring machine. Do not treat the unit test invoking this function as a published performance result.
