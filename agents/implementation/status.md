# Implementation Status

**Latest refresh 2026-10-07:** `just ci` green at **1,488 passing, 90.55% coverage**, strict mypy clean, hygiene and OpenAPI contract pass. The curation programme opens here: the engine gains a deterministic redundancy and near-duplicate measure over signals ingest already computed ([ADR 0032](../decisions/0032-behavioural-fingerprints.md), [EXP-0019](../experiments/0019-behavioural-fingerprint-calibration.md)), and then walked end to end as an operator: the report decides a build and that build exports 4x smaller with every planted behaviour retained ([EXP-0020](../experiments/0020-curation-ab-end-to-end.md)). (Line coverage moves by about 0.02 points between identical runs - the shared test catalog is not empty, and a few integration paths branch on what it already holds - so read the number as ~90.4%, not as a contract.) The paragraphs below this line are the historical MVP hand-off note and are kept for provenance; rows in the table are updated as components change. (The count and the percentage on this line were stale for part of the day: they read 1,413 / 90.05% while the suite had grown to 1,418 and the file had not been refreshed, and an intermediate edit of this line claimed 1,441 before the suite was green. A number in a doc is a claim, and two of them were wrong.)

Updated 2026-09-29, at the MVP hand-off. **All 27 criteria in the MVP section of [spec/definition-of-done.md](../spec/definition-of-done.md) are now checked with evidence**, which closed two gaps that were open a week earlier: the MCAP reader ([ADR 0022](../decisions/0022-mcap-ingest-reader.md)) and the first real-format benchmark baseline ([EXP-0004](../experiments/0004-mcap-ingest-baseline.md)). The suite is at **673 passing, 91.97% coverage**, contract and hygiene clean, mypy strict-clean over 58 modules.

Two things this table should make obvious rather than hide. **Builds are now real** - a build's identity is the SHA-256 of its own manifest, so rebuild determinism is structural and asserted by test, not a convention. **And the performance claim is now honest rather than absent**: MCAP ingest measures 10.8-18.3 MiB/s against a provisional 50 MB/s target (EXP-0005, after the 3.5x B-019 fix), and the record states plainly that the target is unreachable by this design and needs re-scoping by the owner.

All work is committed on `main`. It sits on top of the run-intelligence slice ([ADR 0017](../decisions/0017-runtime-metrics-aggregation.md), [ADR 0018](../decisions/0018-episode-quality-signals.md), [ADR 0021](../decisions/0021-frontend-instrument-pass.md)), validation ([ADR 0016](../decisions/0016-json-validation-profiles.md)), real-format ingest, and the job lifecycle ([ADR 0015](../decisions/0015-cooperative-job-lifecycle.md)). PostgreSQL integration tests pass against a live cluster and skip cleanly without `DE_DATABASE_URL`. Review verdict is **accept with follow-ups**. Two baselines are committed - EXP-0001 (synthetic micro) and EXP-0004 (MCAP); the remaining workloads in EXP-0002/0003 have measured results but **no committed baselines without owner authorization**.

State: `not started` / `stub` / `working` / `hardened`. `working` means exercised for the documented synthetic path, not production-ready.
